## Requirements

- `reservation` 모듈에 **순수 도메인 클래스**와 **JPA Entity**를 명확히 분리한다.
  - `domain` 패키지: JPA 어노테이션이 전혀 없는 `Reservation` 데이터 클래스 + `ReservationStatus` enum
    (같은 파일 `Reservation.kt`).
  - `persistent` 패키지: `@Entity` 클래스 `ReservationEntity` (기존 `Reservation`이라는 이름은 더 이상
    Entity에 쓰지 않는다) + `ReservationRepository`.
- 필드 구성은 Revision 1과 동일하게 확정된 스펙을 따른다: `id`(PK), `platformCode`, `roomId`,
  `userIdentifyCode`, `startDate`, `endDate`, `reservedAt`, `code`(플랫폼 발급 예약 코드, 멱등성 키 —
  `platformCode` + `code` 조합 유니크 제약), `status`(`CONFIRMED`/`CANCELLED`).
- `ReservationStatus`는 각 값에 한글 설명을 담는 `description: String` 필드를 가진다.
  - `CONFIRMED` → `"예약 확정"`
  - `CANCELLED` → `"예약 취소"`
- `ReservationEntity` ↔ `Reservation`(도메인) 간 변환 함수(`toDomain()`/`toEntity()`)를 제공한다.
- `ReservationRepository`는 `JpaRepository<ReservationEntity, Long>`을 확장하며, `findByPlatformCodeAndCode`
  하나만 제공한다 (`existsByPlatformCodeAndCode`는 동일한 where절의 중복 쿼리이므로 제거 — 존재 여부 확인이
  필요하면 `findByPlatformCodeAndCode(...) != null`로 대체한다).
- Repository 테스트는 `@DataJpaTest` 대신 **MockK로 `ReservationRepository`를 mock**해서 작성한다. DB
  유니크 제약을 실제로 위반시켜 검증하는 테스트 케이스는 이 방식으로는 검증할 수 없으므로 제외한다.
- **필수 후속 변경(리뷰에는 없었지만 Entity 이동에 따른 필연적 결과)**: `ReservationEntity`가
  `reservation.domain`이 아니라 `reservation.persistent` 패키지로 이동하므로,
  `ReservationApplication.kt`의 `@EntityScan(basePackages = [...])`도 `"yeo.chi.proejct.pms.reservation.domain"`
  에서 `"yeo.chi.proejct.pms.reservation.persistent"`로 함께 수정해야 한다. 이걸 빠뜨리면 Hibernate가
  `ReservationEntity`를 전혀 인식하지 못해 애플리케이션이 부팅 시 깨진다.

## Technical Approach

### 1. `domain/Reservation.kt` — 순수 도메인 (신규, JPA 의존성 없음)

`Reservation` 데이터 클래스와 `ReservationStatus` enum을 같은 파일에 둔다. 이 파일은 `jakarta.persistence.*`를
전혀 import하지 않으며, `persistent` 패키지도 import하지 않는다 (도메인이 영속성 계층을 알아서는 안 됨 —
방향은 항상 `persistent → domain`).

```kotlin
package yeo.chi.proejct.pms.reservation.domain

import java.time.LocalDate
import java.time.LocalDateTime

data class Reservation(
    val platformCode: String,
    val roomId: Long,
    val userIdentifyCode: String,
    val startDate: LocalDate,
    val endDate: LocalDate,
    val reservedAt: LocalDateTime,
    val code: String,
    val status: ReservationStatus = ReservationStatus.CONFIRMED,
    val id: Long? = null,
)

enum class ReservationStatus(val description: String) {
    CONFIRMED("예약 확정"),
    CANCELLED("예약 취소"),
}
```

### 2. `persistent/ReservationEntity.kt` — JPA Entity + 변환 함수 (신규, `Reservation.kt`를 대체)

Entity는 여전히 `platformCode` + `code` 유니크 제약을 갖는다. `id`/`status`는 외부(다른 모듈)에서 마음대로
바꾸지 못하도록 `internal set`으로 캡슐화한다 — `protected set`이 아니라 `internal set`을 쓰는 이유는, 아래
`toEntity()` 확장 함수가 (같은 클래스 본문이 아니라) 같은 파일의 top-level 함수이기 때문에 `protected`로는
접근할 수 없기 때문이다. `internal`은 Kotlin에서 "같은 Gradle 모듈"까지 접근을 허용하므로, `reservation`
모듈 밖(`operation` 등)에서는 여전히 막히면서 같은 모듈의 매퍼 함수/테스트 코드에서는 문제없이 값을 설정할
수 있다 (Kotlin Gradle 플러그인이 같은 서브프로젝트의 `test` 소스셋을 `main`의 friend 컴파일로 취급하므로
테스트 코드에서도 접근 가능).

```kotlin
package yeo.chi.proejct.pms.reservation.persistent

import jakarta.persistence.Column
import jakarta.persistence.Entity
import jakarta.persistence.EnumType
import jakarta.persistence.Enumerated
import jakarta.persistence.GeneratedValue
import jakarta.persistence.GenerationType
import jakarta.persistence.Id
import jakarta.persistence.Table
import jakarta.persistence.UniqueConstraint
import yeo.chi.proejct.pms.reservation.domain.Reservation
import yeo.chi.proejct.pms.reservation.domain.ReservationStatus
import java.time.LocalDate
import java.time.LocalDateTime

@Entity
@Table(
    name = "reservation",
    uniqueConstraints = [
        UniqueConstraint(
            name = "uk_reservation_platform_code_code",
            columnNames = ["platform_code", "code"],
        ),
    ],
)
class ReservationEntity(
    @Column(name = "platform_code", nullable = false, updatable = false)
    val platformCode: String,

    @Column(name = "room_id", nullable = false, updatable = false)
    val roomId: Long,

    @Column(name = "user_identify_code", nullable = false, updatable = false)
    val userIdentifyCode: String,

    @Column(name = "start_date", nullable = false, updatable = false)
    val startDate: LocalDate,

    @Column(name = "end_date", nullable = false, updatable = false)
    val endDate: LocalDate,

    @Column(name = "reserved_at", nullable = false, updatable = false)
    val reservedAt: LocalDateTime,

    // 플랫폼이 발급한 예약 코드. platformCode + code 조합이 멱등성 키이며,
    // 위 @Table(uniqueConstraints=...)로 DB 레벨 중복 저장을 막는다.
    @Column(name = "code", nullable = false, updatable = false)
    val code: String,
) {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id")
    var id: Long? = null
        internal set

    @Enumerated(EnumType.STRING)
    @Column(name = "status", nullable = false)
    var status: ReservationStatus = ReservationStatus.CONFIRMED
        internal set
}

fun ReservationEntity.toDomain(): Reservation = Reservation(
    platformCode = platformCode,
    roomId = roomId,
    userIdentifyCode = userIdentifyCode,
    startDate = startDate,
    endDate = endDate,
    reservedAt = reservedAt,
    code = code,
    status = status,
    id = id,
)

fun Reservation.toEntity(): ReservationEntity {
    val entity = ReservationEntity(
        platformCode = platformCode,
        roomId = roomId,
        userIdentifyCode = userIdentifyCode,
        startDate = startDate,
        endDate = endDate,
        reservedAt = reservedAt,
        code = code,
    )
    entity.id = id
    entity.status = status
    return entity
}
```

설계 노트: `toDomain()`은 `ReservationEntity`의 확장 함수로, `toEntity()`는 `Reservation`의 확장 함수로 두되
**둘 다 이 파일(`persistent/ReservationEntity.kt`)에 정의**한다. 이렇게 하면 `domain/Reservation.kt`는
`persistent` 패키지를 전혀 몰라도 되고(의존 방향: `persistent → domain`만 존재), 그러면서도 사용하는 쪽에서는
`entity.toDomain()` / `reservation.toEntity()`처럼 자연스럽게 호출할 수 있다. (리뷰에서 요구한 "변환 함수"의
정확한 배치 위치까지는 명시되지 않았으나, 순수 도메인 원칙을 지키기 위해 이 배치를 권장한다. 이견이 있으면
구현 시 조정 가능.)

### 3. `persistent/ReservationRepository.kt`

`existsByPlatformCodeAndCode` 제거. `findByPlatformCodeAndCode`만 남기고, 존재 여부 확인이 필요한 호출부는
`findByPlatformCodeAndCode(...) != null`로 대체한다.

```kotlin
package yeo.chi.proejct.pms.reservation.persistent

import org.springframework.data.jpa.repository.JpaRepository

interface ReservationRepository : JpaRepository<ReservationEntity, Long> {

    fun findByPlatformCodeAndCode(platformCode: String, code: String): ReservationEntity?
}
```

### 4. `ReservationApplication.kt` 수정 (필수)

`@EntityScan`의 `basePackages`에서 `"yeo.chi.proejct.pms.reservation.domain"`을
`"yeo.chi.proejct.pms.reservation.persistent"`로 교체한다 (`@ComponentScan`은 이미
`"yeo.chi.proejct.pms.reservation"` 전체를 포함하고 있어 수정 불필요 — `persistent` 하위 패키지의
`ReservationRepository`도 기본 Spring Data JPA 리포지토리 스캔 범위에 그대로 포함됨).

```kotlin
@EntityScan(
    basePackages = [
        "yeo.chi.proejct.pms.reservation.persistent",
        "yeo.chi.proejct.pms.operation.domain",
    ],
)
```

### 5. 삭제 대상 파일

- `reservation/src/main/kotlin/yeo/chi/proejct/pms/reservation/domain/ReservationStatus.kt` (내용은
  `domain/Reservation.kt`로 흡수)
- 기존 `reservation/src/main/kotlin/yeo/chi/proejct/pms/reservation/domain/Reservation.kt` (JPA `@Entity`
  버전) — `persistent/ReservationEntity.kt`로 대체되고, `domain/Reservation.kt`는 순수 도메인 버전으로
  새로 작성됨.

### 6. Edge cases

- `Reservation`(도메인)이 `data class`이므로 `id = null`인 두 개의 "아직 저장 전" 도메인 인스턴스는 나머지
  필드가 같으면 `equals()`상 동일하게 취급된다 — 저장 전 임시 객체를 컬렉션 키 등으로 쓰지 않도록 주의
  (이번 티켓 범위에서는 해당 사용처 없음).
- `internal set`은 `reservation` 모듈 내부에서는 누구나 `id`/`status`를 바꿀 수 있다는 뜻이므로, `service`
  계층(#3)에서 임의로 `entity.status = ...`를 직접 대입하지 않고 도메인 객체를 통해 상태를 표현한 뒤
  `toEntity()`로 다시 매핑하는 흐름을 권장 컨벤션으로 문서화해 둔다 (강제하는 컴파일 규칙은 아님).
- `existsByPlatformCodeAndCode` 제거로 인해 만약 다른 곳에서 이미 그 메서드를 참조하고 있었다면(현재는
  없음) 컴파일 에러가 나므로, 구현 시 전체 검색으로 사용처가 없는지 한 번 더 확인한다.
- MockK 기반 테스트는 `ReservationRepository`의 "실제 SQL 동작"이 아니라 "Repository를 사용하는 코드가
  Repository 인터페이스를 올바르게 호출/처리하는지"를 검증하는 것이라는 한계를 인지한다. 이번 티켓은 아직
  Repository를 호출하는 서비스 코드가 없으므로(그건 #3), 이 테스트는 사실상 매퍼(`toEntity`/`toDomain`)와
  Repository 인터페이스 시그니처에 대한 사용 예시/스모크 테스트 성격이 강하다. 실제 DB 제약조건(유니크
  제약 등) 검증이 필요해지면 추후 별도 티켓에서 `@DataJpaTest` 통합 테스트를 다시 추가하는 방안을 고려한다.

## Testing Plan

`ReservationRepository`를 MockK로 mock하여 단위 테스트로 작성한다 (`@DataJpaTest`/실제 H2 연동 없음).

`reservation/src/test/kotlin/yeo/chi/proejct/pms/reservation/persistent/ReservationRepositoryTest.kt`:

```kotlin
package yeo.chi.proejct.pms.reservation.persistent

import io.kotest.matchers.nulls.shouldBeNull
import io.kotest.matchers.nulls.shouldNotBeNull
import io.kotest.matchers.shouldBe
import io.mockk.every
import io.mockk.mockk
import io.mockk.verify
import org.junit.jupiter.api.Test
import yeo.chi.proejct.pms.reservation.domain.Reservation
import java.time.LocalDate
import java.time.LocalDateTime

class ReservationRepositoryTest {

    private val reservationRepository = mockk<ReservationRepository>()

    private fun newReservation(
        platformCode: String = "AIRBNB",
        code: String = "AIRBNB-CODE-0001",
    ) = Reservation(
        platformCode = platformCode,
        roomId = 1L,
        userIdentifyCode = "guest-001",
        startDate = LocalDate.of(2026, 9, 1),
        endDate = LocalDate.of(2026, 9, 3),
        reservedAt = LocalDateTime.of(2026, 8, 13, 10, 0),
        code = code,
    )

    @Test
    fun `save 호출 시 id가 채번된 엔티티가 반환된다`() {
        val entityToSave = newReservation().toEntity()
        val savedEntity = newReservation().toEntity().apply { id = 100L }
        every { reservationRepository.save(entityToSave) } returns savedEntity

        val result = reservationRepository.save(entityToSave)

        result.id shouldBe 100L
        result.platformCode shouldBe "AIRBNB"
        verify(exactly = 1) { reservationRepository.save(entityToSave) }
    }

    @Test
    fun `findByPlatformCodeAndCode로 조회되면 도메인으로 변환 가능한 엔티티를 반환한다`() {
        val entity = newReservation().toEntity().apply { id = 1L }
        every { reservationRepository.findByPlatformCodeAndCode("AIRBNB", "AIRBNB-CODE-0001") } returns entity

        val found = reservationRepository.findByPlatformCodeAndCode("AIRBNB", "AIRBNB-CODE-0001")

        found.shouldNotBeNull()
        found.toDomain().code shouldBe "AIRBNB-CODE-0001"
    }

    @Test
    fun `findByPlatformCodeAndCode로 조회되지 않으면 null을 반환한다 (존재 여부는 null 체크로 판단)`() {
        every { reservationRepository.findByPlatformCodeAndCode("AIRBNB", "NO-SUCH-CODE") } returns null

        val found = reservationRepository.findByPlatformCodeAndCode("AIRBNB", "NO-SUCH-CODE")

        found.shouldBeNull()
    }
}
```

추가로 매퍼 자체에 대한 순수 단위 테스트(Spring/MockK 불필요)도 함께 작성해 `toDomain()`/`toEntity()`
왕복 변환이 필드 누락 없이 정확한지 검증한다.
